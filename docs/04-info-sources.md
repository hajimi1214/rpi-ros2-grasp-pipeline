# 信息源规则：三源交叉，信踩坑的不信官方的

## 为什么这条要写进仓库

官方信息给的是**设计意图**，非官方信息才是**实际结果**。两者对不上的时候，永远信后者。

三种最容易骗人的官方信息：

| 类型 | 它说什么 | 实际是什么 |
|------|----------|------------|
| 招聘 JD | "熟悉 ROS2、有嵌入式 AI 经验优先" | HR 抄模板堆关键词。写"3年经验"的岗可能实际招应届，写"熟悉ROS"的可能团队里没人真用过 |
| 官方教程 | ROS2 Tutorials 跑通了就算会 | 只讲 happy path。不讲多机 DDS 组网被防火墙阻断、不讲 arm64 编译失败、不讲版本不兼容 |
| 厂商 benchmark | "树莓派 5 上 30 FPS" | 理想条件：关桌面、加散热、特定 batch size、特定输入尺寸。真实跑不到 |

---

## 三源交叉规则

**任何一条影响决策的关键信息，至少找三个来源：**

1. 官方说法（知道它的口径是什么）
2. 一个从业者的真实说法（他实际在干什么/遇到了什么）
3. 一个踩坑记录（别人报错的原文）

**两个对不上就信踩坑的。** 官方和从业者冲突，信从业者；从业者和踩坑帖冲突，信踩坑帖——因为踩坑帖有报错原文和时间戳，最难造假。

## 本项目该去哪挖真信息

### 关于"这个岗位到底要什么"（决定我力气往哪使）

| 来源 | 搜什么 | 能看到什么 |
|------|--------|-----------|
| 牛客网 | `嵌入式 实习 面经` `机器人 面经` | 真实面试被问了什么题。**比 JD 准十倍** |
| 看准 / 脉脉 | 目标公司名 | 真实加班情况、团队规模、实习生到底干什么活 |
| 小红书 / B站 | `嵌入式劝退` `机器人 实习 真实` `算法岗 学历` | 从业者吐槽：哪些技能其实用不上、哪些才是真门槛 |
| 知乎 | `本科 机器人 就业` `非科班 嵌入式` | 长文，能看清行业结构和学历天花板 |
| 目标公司 GitHub | 公司名 / 团队开源仓库 | **他们实际用的技术栈，比 JD 准**。JD 写 ROS，仓库里全是自研框架的情况很常见 |

### 关于"这个技术到底能不能跑通"（决定我明天别白装）

| 来源 | 搜什么 | 为什么必须看 |
|------|--------|-------------|
| GitHub Issues | `Jazzy raspberry pi` `ROS2 arm64 build failed` | 官方教程不会写的真实报错，带版本号和时间 |
| ROS Answers | 具体报错原文 | 提问的人和回答问题的人都是真跑过的人 |
| 中文社区 / CSDN / 博客园 | `树莓派5 ROS2 踩坑` | 中文环境特有的网络、镜像源问题 |
| Reddit r/ROS / Discord | `Pi5 Jazzy anyone got it working` | 英文社区回复快，且敢说"别用这个方案" |

**明天装 Ubuntu 之前，先去搜一句**：`RTX 5060 Ubuntu 24.04 driver`。这是本项目最可能翻车的一个点——50 系是较新的卡，24.04 上 Nouveau 开源驱动能不能撑到装完专有驱动、需不需要先加 PPA，官方安装文档不会写，但肯定有人踩过。搜完再动手，省一晚上。

### 关于"什么样的项目才算拿得出手"（决定我做成什么样）

这条最容易自欺。不要问"我这个项目够不够好"，去搜反面：

- 小红书 / 知乎搜：`面试官 看项目` `简历项目 机器人` `应届 项目 没含金量`
- 牛客搜：`简历 项目 被问穿`
- 关键词：**"培训班项目"**、**"烂大街项目"** —— 看看面试官吐槽的是哪几类

**目前已知的判据（待用真实帖验证）：**

面试官判断一个项目真不真，通常只问三句：
1. "你这个延迟多少？瓶颈在哪？" → 对应 `01-metrics.md` 的延迟预算拆解，**答不上就露馅**
2. "为什么选这个方案不选那个？" → 对应选型理由，README 里必须写清楚为什么是半实物
3. "遇到什么问题？怎么解决的？" → 对应 `02-weekly-log.md`，**没记录就编不出来，编的经不起追问**

这三句答不上，项目做得再花哨也白搭。

## 卡住时该去哪问

搜索是找别人写过的，提问是让人现场帮你。两者分开。

|----------|------|------|
| 装系统 / 装 ROS2 报错、国内网络问题 | **鱼香社区论坛** fishros.org.cn/forum | **中文，首选**。作者小鱼本人和群友在线，是最快的一条路 |
| 急着要答案 | 鱼香 QQ 群 **139707339**（口令 `d2lros2+fishros`）；一键安装群 **438144612**（口令 `一键安装`） | 实时，但回答质量看运气 |
| 具体报错、TF 树断了、概念不懂 | **Robotics Stack Exchange** robotics.stackexchange.com | 2023 年已吸收原来的 ROS Answers。**先搜再问**，90% 的问题被问过 |
| 架构选型、版本兼容、要不要这么做 | **ROS Discourse** discourse.ros.org | 官方论坛，长篇技术讨论，**维护者真的会回** |

| 不敢用英文问 | 古月居 guyuehome.com、知乎 ROS 话题 | |

### 最被低估的一招：读 closed issues

你依赖的包（MoveIt2、Gazebo、ros2_control）的 **issue 列表本身就是最好的调试资料**。尤其是那些**已关闭**的——里面往往有"我也遇到了，原因是 XXX，解决办法是 YYY"的完整过程，比文档详细，比教程真实。

遇到怪问题先去搜：`仓库名 + 报错关键词`，看 closed 的。

### 提问模板（照抄，回答率差很多）

社区冷不冷淡是次要的，**提问质量才决定有没有人回**。发帖必须带这四项：

```
环境：Ubuntu 24.04 + ROS2 Jazzy（树莓派 5 / PC 写清楚）
现象：贴完整报错原文，不要只写"报错了"
我试过：1. ___ 2. ___ 3. ___
代码/命令：贴最小可复现的那几行，不要整个项目
```

**贴完整报错原文**这一条最容易漏，也最影响回答率。

## 执行要求

- 每次要做一个**影响方向**的判断（换技术栈、换岗位方向、决定是否值得投入），必须先走三源交叉，不许只看一篇官方/AI 给的答案就定
- 搜到的关键信息，把**链接和结论**记进对应文档，别只记结论——过两个月会忘，也分不清是自己想的还是抄的
- 特别留意**评论区**：帖子正文常常是理想情况，评论区才有人写"我按这个做失败了，原因是……"
