# 指标表（待填数字清单）

这张表是这个项目唯一真正值钱的东西。空着的时候 README 只是个想法，填完才是项目。

每一项都写清楚了**怎么测**，照做即可，不需要再设计方法。

---

## 一、端侧推理（跑在树莓派上）

| 指标 | 待填 | 怎么测 | 什么时候能填 |
|------|------|--------|--------------|
| 模型名称 / 输入尺寸 | | 记下来就行 | P0 |
| FP32 推理 FPS | | 连续跑 100 帧，取均值。**不要取单帧** | P0 |
| INT8 推理 FPS | | 同上，量化后再测一次 | P1 |
| 单帧端到端延迟 | | 从`拿到图像时间戳`到`发布位姿时间戳`的差值，用 ROS2 消息头里的 stamp 算 | P0 |
| CPU 占用率 | | `top` 跑 60 秒取均值 | P0 |
| 内存占用 | | `free -h` 峰值 | P0 |
| 温度（满载 10 分钟后） | | `vcgencmd measure_temp`（Pi 专用） | P0 |
| INT8 相对 FP32 的精度损失 | | 同一组 100 张测试图，对比 mAP 或检测框 IoU | P1 |

**注意**：测 FPS 必须关掉桌面环境（`sudo systemctl set-default multi-user.target`），否则桌面合成器会吃掉 10~20% 的性能，数字会偏低。

## 三、执行侧（PC + Gazebo 仿真）

| 指标 | 待填 | 怎么测 |
|------|------|--------|
| 抓取成功率 | | **至少 50 次**，开域随机化（随机目标位置/光照/摩擦），记成功次数 |
| 单次抓取周期耗时 | | 从`收到位姿`到`放置完成` |
| 位姿估计误差 | | 仿真里能拿到 ground truth，直接算差值 |

成功率只有跑够 50 次才有意义，跑 5 次全成功说明不了任何问题。

---

## 四、延迟预算拆解（P2 必须做）

面试最容易被问的一句："**端到端延迟多少？瓶颈在哪？**"

把总延迟拆成四段，每段单独计时：

```
摄像头采集  →  网络传输  →  推理  →  控制下发  →  机械臂执行
   ?ms          ?ms         ?ms        ?ms           ?ms
```

填完这张表，"你的项目延迟多少"这个问题就变成了加分题而不是送命题。
